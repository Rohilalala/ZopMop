# Roomies Feature — Redesigned Implementation Plan

**Project:** ZopMop / househelp-api + zopmop-app  
**Module:** `internal/roomies` (Go) + React Native UI  
**Date:** 2026-04-13 (redesign)

---

## Overview of Design Change

The original plan exposed Roomies as a standalone dashboard reachable from a HomeScreen banner. The new design embeds it into natural product surfaces:

- **Entry:** Profile section → Roomies (setup / join)
- **Home:** When a roomies-enabled address is the selected address, a "Manage Household" button appears in the home screen header (top right)
- **No persistent banner** on the home screen

---

## User Flows

### Flow A — Host: Create a group
```
ProfileScreen
  → [Roomies row]
  → RoomiesSetupScreen  (no active group state)
    → "Enable for my address"
    → [list of saved addresses]
    → [select address]
    → POST /roomies/groups  →  6-digit code generated
    → RoomiesCodeShareScreen
        Shows: code, "Share with up to 3 roommates", copy/share button
```

### Flow B — Member: Join with a code
```
ProfileScreen
  → [Roomies row]
  → RoomiesSetupScreen  (no active group state)
    → "Join with a code"
    → RoomiesJoinScreen  (6-digit code input)
    → POST /roomies/groups/join
        Backend: validates code, checks capacity (<4 members), joins user,
                 auto-copies address to user's profile if not already saved
    → RoomiesWelcomeScreen  (dynamic splash)
        Shows: group name, address label, animated welcome
    → [dismiss → back to Home]
```

### Flow C — Already in a group (both host and member)
```
ProfileScreen
  → [Roomies row]
  → RoomiesSetupScreen  (active group state)
      Shows: group name, address, member count, your invite code (if host)
      Options: Leave group / Delete group (host only)
```

### Flow D — Manage Household (from Home)
```
HomeScreen  (roomies-enabled address is selected)
  → "Manage Household" button  (top-right of header)
  → ManageHouseholdScreen
      Tabs: Vault | Ledger
      Vault tab:  total household balance, per-member balances, Add Balance button
      Ledger tab: active debts, settle button → SettlementModal
```

## Phase 1 — Database Migration Changes

**File:** `App/househelp-api/migrations/026_create_roomies_schema.sql`

### Additions needed

```sql
-- Add invite code to address_groups
ALTER TABLE address_groups
  ADD COLUMN invite_code CHAR(6) NOT NULL DEFAULT '',
  ADD CONSTRAINT uq_address_groups_invite_code UNIQUE (invite_code);

-- Add max_members constraint enforced at application layer (not DB)
-- Max = 4 (host + 3 members), checked in service before INSERT into address_members

-- Auto-copy address on join: handled in Go service, not SQL
-- The service will INSERT into user_addresses if the address_id isn't already linked to the joining user
```

**Note:** `invite_code` is a 6-digit numeric string (e.g. `"483921"`), generated by the service using `crypto/rand` to avoid collisions, with a retry loop on unique constraint violation.

## Phase 2 — Backend Changes

### 2a. model.go additions

```go
// Add to AddressGroup struct:
InviteCode string `json:"invite_code"`

// New request type:
type JoinGroupRequest struct {
    Code string `json:"code" validate:"required,len=6"`
}

// New response type:
type JoinGroupResponse struct {
    Group        AddressGroup  `json:"group"`
    AddressAdded bool          `json:"address_added"` // true if address was auto-copied to user profile
    AddressLabel string        `json:"address_label"`
}

// New response type for GET /groups/me:
type MyGroupResponse struct {
    Group    AddressGroup    `json:"group"`
    Members  []AddressMember `json:"members"`
    MyRole   MemberRole      `json:"my_role"`
}
```

### 2b. repository.go additions

| Method | SQL operation |
|--------|--------------|
| `CreateGroup(ctx, hostUserID, addressID, name, code string)` | INSERT into `address_groups` with `invite_code` |
| `GetGroupByCode(ctx, code string)` | SELECT from `address_groups` WHERE `invite_code = $1` |
| `GetGroupByUserID(ctx, userID string)` | SELECT via JOIN on `address_members` WHERE `user_id = $1` |
| `GetMemberCount(ctx, groupID string)` | SELECT COUNT from `address_members` |
| `AddMember(ctx, userID, groupID string)` | INSERT into `address_members` with role='member' |
| `CopyAddressToUser(ctx, userID, addressID string)` | INSERT into `user_addresses` if not exists (SELECT + conditional INSERT in txn) |

### 2c. service.go additions

| Method | Logic |
|--------|-------|
| `GenerateUniqueCode(ctx)` | Loop: `crypto/rand` 6-digit int → try `GetGroupByCode` → retry on collision |
| `CreateGroup(ctx, req CreateGroupRequest, hostUserID string)` | Generate code → INSERT group + INSERT host member in txn |
| `JoinGroup(ctx, req JoinGroupRequest, userID string)` | Get group by code → check capacity (≤3 existing members) → txn: AddMember + CopyAddressToUser → return JoinGroupResponse |
| `GetMyGroup(ctx, userID string)` | GetGroupByUserID → GetMembers → return MyGroupResponse or nil |

### 2d. handler.go route changes

| Method | Route | Handler |
|--------|-------|---------|
| POST | `/roomies/groups` | `CreateGroup` (updated — now returns `invite_code`) |
| POST | `/roomies/groups/join` | `JoinGroup` (new) |
| GET | `/roomies/groups/me` | `GetMyGroup` (new) |
| DELETE | `/roomies/groups/:id/members/:userID` | `LeaveGroup` (existing) |
| DELETE | `/roomies/groups/:id` | `DeleteGroup` (existing) |
| GET | `/roomies/groups/:id/vault` | `GetVault` (existing) |
| GET | `/roomies/groups/:id/debts` | `GetDebts` (existing) |
| POST | `/roomies/members/:memberID/topup` | `TopUp` (existing) |
| POST | `/roomies/groups/:id/book` | `BookGroupChore` (existing) |

**Removed route:** `POST /roomies/groups/:id/members` (invite by userID — replaced by code join)

### 2e. Capacity enforcement

In `JoinGroup` service method, before inserting:
```
memberCount = GetMemberCount(ctx, group.ID)
if memberCount >= 4 {
    return 409 Conflict: "group is full"
}
```

## Phase 4 — Address Auto-Copy Logic

When a member joins via code, the backend must ensure the group's address is in their `user_addresses` table. The service does:

1. `SELECT id FROM user_addresses WHERE user_id = $joiningUserID AND address_id = $groupAddressID`
2. If not found: `INSERT INTO user_addresses (user_id, address_id, ...) SELECT $joiningUserID, address, ... FROM user_addresses WHERE id = $groupAddressID`
   - Copies all address fields, sets `is_default = false`
3. Returns `address_added: true/false` in `JoinGroupResponse`

This ensures the address shows in the joiner's address picker automatically.

## Phase 5 — Edge Cases

| Case | Handling |
|------|---------|
| User tries to join when already in a group | 409: "You are already in a household group" |
| Group is full (4 members) | 409: "This household is full" |
| Invalid / expired code | 404: "No household found with this code" |
| Host leaves their own group | 400: "Transfer host before leaving, or delete the group" |
| Joining user's address already saved | `address_added: false`, no duplicate insert |
| Host creates group for address already in another group | 409: "This address already has a household" (add UNIQUE constraint on `address_groups.address_id`) |
